# 공식 효과 패키지 기본 설치 시간(첫 실행)

기본 효과를 공식 스크립트 효과 패키지 23개(`chickxel.effects.<ID>`)로 바꾸면서, 앱은 처음 실행할 때(그리고 앱에 든 버전이 더 새로울 때) 그 패키지를 만들어(미리보기 APNG 포함) 에셋 저장소에 설치한다(`OfficialEffectPackages.Sync`). 이것을 UI 스레드에서 하면 첫 실행에 창이 멈추는지 재고, 300ms를 넘으면 UI 스레드 밖으로 옮기기로 했다.

## 환경

- 날짜: 2026-11-01, Windows 11 x64(10.0.26200), Intel Core i5-13400F, NVMe SSD, .NET SDK 10.0.300, Release.
- 저장소: 새 임시 폴더(`AssetStore.Open`), 공식 효과 23개, 각 패키지 = 스크립트 + APNG 미리보기 + 효과 없는 원본 PNG + LICENSE·README.
- 방법: `dotnet run` 파일 기반 프로그램(Core 프로젝트 참조)으로 `Stopwatch`. 같은 프로세스에서 새 폴더로 3~4번(첫 번은 JIT·첫 읽기 포함). 측정 코드는 저장소에 넣지 않았다(임시 폴더에서 돌림).
- 둘째 표의 백그라운드 시간은 GuideShots를 함께 돌리던 중이라 부하가 있었다.

## 결과: 예전처럼 UI 스레드에서 한 번에

| 항목 | 첫 번(차가움) | 다음 번들 |
|---|---|---|
| `Sync` 전체(만들기 + 설치 23개) | 2917ms | 962~1446ms |
| 만들기만(`Build` 23개, 따뜻함) | - | 1430ms |
| 설치만(미리 만든 패키지 바이트 26개, `AssetStore.Install`) | 1501ms | 489~528ms |
| 이미 설치된 뒤 다시 열기 + `Sync`(할 일 없음) | 16~28ms | |

미리 만든 패키지 바이트를 앱에 넣어도 설치만 0.5~1.5초라 300ms를 넘는다(설치마다 상태 파일을 쓰고 카탈로그를 다시 읽음). 그래서 만들기와 설치를 모두 UI 스레드 밖으로 옮겼다.

## 결과: 백그라운드로 옮긴 뒤 UI 스레드가 하는 일

앱(`AppAssets.Store`)은 저장소를 열고 `OfficialEffectPackages.NeedsSync`로 할 일이 있을 때만 같은 폴더의 다른 저장소 객체로 백그라운드에서 `Sync`를 돌린 뒤, UI 스레드에서 `AssetStore.Refresh`로 다시 읽는다(`Changed` → 효과 탭·에셋 관리자 다시 그림).

| 항목(UI 스레드) | 첫 번 | 다음 번들 |
|---|---|---|
| 저장소 열기 | 16ms | 4~7ms |
| `NeedsSync`(새 저장소) | 82ms(공식 원문·등록 차례 처음 읽기 포함) | 0.03~0.04ms |
| 백그라운드 `Sync`(UI 스레드 아님, 부하 있음) | 3609ms | 1581~3915ms |
| 끝난 뒤 `Refresh`(패키지 23개 다시 읽기) | 56ms | 19~20ms |
| 다음 실행: 열기 + `NeedsSync`(할 일 없음) | 25 + 10ms | 15~18 + 1.2~1.6ms |

## 결론과 남은 문제

- 첫 실행에 UI 스레드가 쓰는 시간은 100ms 아래(열기 + `NeedsSync` + 끝난 뒤 `Refresh`)로, 300ms 기준 안이다. 공식 효과는 설치가 끝나면(첫 실행에 1~4초) 효과 탭에 나타난다.
- "기본 효과 되돌리기"도 같은 백그라운드 길을 쓴다(단추를 끄고 기다림).
- 백그라운드 설치는 다른 저장소 객체라 잠금 파일로 차례를 정한다. 저장소를 열 때의 정리(Staging 비우기·반쯤 된 설치 지우기)는 잠금을 바로 잡을 수 있을 때만 하도록 바꿨다(다른 쪽이 설치 중인 폴더를 지우지 않게).
