# F1 사용 가이드 가독성: 다시 쓰기 전후 점수

## 무엇을 왜 쟀나

F1 사용 가이드(= 홈페이지 가이드, `docs/i18n/guide/*`)가 길고 구현 세부가 많아 읽기 어렵다는 판단에서, 장마다 다시 쓰기 전후를 같은 잣대로 쟀다. 잣대는 도움말 작성 지침에서 가져왔다.

- NN/g 사용성 원칙 10(도움말): 찾기 쉽게, 과제 중심, 구체적 단계, 너무 크지 않게, 개요를 위에.
- Microsoft Style Guide — Scannable content: 중요한 것 먼저, 짧은 문장·문단, 같은 틀.
- Diátaxis: 하는 법·참조·설명을 섞지 않기. Minimalism(Carroll): 읽기보다 하기.

## 환경

- Windows 10.0.26200 x64, Python 3.12, 앱 쪽 데이터는 `python tools/build-docs.py`가 만든 `help.ko.json`(한국어 쪽으로 점수, F1 자리는 영어 쪽으로 확인).
- LLM 평가: eval `judge_batch`(openai-codex/gpt-6-sol), 쪽마다 한 번.
- 점검 스크립트는 저장소 밖(`%TEMP%\helpcheck\helpcheck.py`, 작업 뒤 지움).

## 방법

- **구조 점수(0~100, 쪽마다)**: 한국어 본문 글자 수(1,200자 이하 만점 ~ 4,000자 0점, 25점), 첫 문단 길이(120자 이하 15점), 180자 넘는 문단 비율(15점), 평균 문장 길이(45자 이하 만점 ~ 90자 0점, 10점), 소제목당 글자 수(15점), 그림 유무(10점), 코드의 F1 자리가 찾아지는 비율(10점).
- **LLM 평가(4점 → 100점 환산)**: 과제 먼저(첫 두 줄로 무엇·언제를 아나), 간결(구현 세부·예외·반복이 적나), 훑어보기(짧은 문단·소제목·목록·표), 쉬운 말.
- **F1 자리**: 코드의 `.HelpAt(쪽, anchor:/shot:)`를 정적으로 읽어 `HelpWindow.FindAnchor`와 같은 규칙으로 영어 쪽에서 찾고, 한국어 쪽이 같은 자리 모양인지(SameSpot) 확인. 상수로 넘기는 자리(`new HelpTarget`, `At(...)` 등)는 따로 확인.
- 가이드 첫 화면과 용어 모음 쪽은 뺐다. 두 번째 다듬기는 첫 평가에서 평균 2.5점(4점 만점) 아래인 101쪽만 다시 고쳤다.

## 결론과 남은 문제

- 길이와 구조는 목표에 닿았다. LLM의 간결·쉬운 말 점수는 올랐지만 아직 50 안팎이다. 남은 낮은 쪽은 대부분 참조 성격(스크립트 API, 픽셀로 정리 점수 기준, 효과 종류 표)이라 전문어를 다 뺄 수 없다.
- LLM 평가는 작은 모델 한 번씩이라 쪽마다 ±1점쯤 흔들릴 수 있다. 장 평균으로 보는 것이 맞다.
- 일부 쪽은 정보를 줄였다(효과 설정의 숫자 범위, 메뉴 항목 전체 목록, 확대 단계 등 — 앱 화면에 보이는 것). 필요하면 되살린다.
- `도움말-대기.md` 항목은 반영하지 않았다(키 이름은 그대로 둠).
