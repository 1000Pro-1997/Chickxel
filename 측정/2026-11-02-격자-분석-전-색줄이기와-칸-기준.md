# 격자 찾기 전 색 줄이기, 칸 크기 기준(색 경계) 시험

Pixel Snapper 비교([2026-11-02-pixel-snapper-비교.md](2026-11-02-pixel-snapper-비교.md))에서 나온 두 생각이 AI 그림 픽셀로 정리에 도움이 되는지 쟀다. 좋으면 자동 최적화의 바꿔 볼 항목으로 넣을 생각이었다.

1. 분석 전에 색 줄이기: Snapper처럼 그림 전체를 RGB k-means로 줄인 뒤 격자를 찾으면 번진 가장자리의 가짜 경계가 사라질까.
2. 칸 크기 기준: 기본(크기를 줄여서 = 외곽선 두께)보다 색 경계 쪽이 세부를 더 지킬까.

## 환경

- 날짜: 2026-11-02, Windows 11 x64(10.0.26200), Intel Core i5-13400F, .NET SDK 10.0.300 Release.
- `dotnet run` 파일 기반 프로그램(Core 프로젝트 참조)과 Python(Pillow·NumPy). 측정 코드는 저장소에 넣지 않았다(임시 폴더에서 돌림).
- 색 줄이기는 Snapper와 같은 RGB k-means(k-means++ 시작, 씨앗 42, 15번, 알파 그대로)로 입력 그림을 바꾼 뒤 `Pixelator.Run`. 그래서 칸 색·점수도 줄인 그림 기준이다 — 점수는 비교하지 않고 칸 크기·결과 크기만 본다.

## 1. 정답이 있는 합성 그림

- 원본: `docs/assets/mascot/*.png` 20장(14~19px, 6~13색, 1px 외곽선)과 `tools/GuideShots/Sample/wolf.png`(49×98).
- AI 흉내: 3px 여백 → 칸 크기 k = 5·8·12, 열·행마다 k−1~k+1(5는 k~k+1)로 흔들림 → 가우스 흐림(σ = 0.6k/8 또는 1.2k/8, 알파 포함) → 채널 잡음(±3 또는 ±6) → JPEG(90 또는 75). 21장 × 3 × 2 = 126장. `chick-easel`은 프레임 나누기가 이젤을 따로 떼어 모든 변형에서 크기가 틀려 뺐다(120장).
- 맞음 = 결과 불투명 범위 크기가 원본과 같음.

| 변형 | 크기 맞음 | 크기 틀린 칸 수(평균) | 찾은 칸 ÷ 진짜 칸(중앙값, p10~p90) |
|---|---|---|---|
| 지금(색 줄이지 않음) | 120/120 (100%) | 0 | 1.01 (0.99~1.08) |
| 8색으로 줄인 뒤 | 95.0% | 2.0 | |
| 16색으로 줄인 뒤 | 92.5% | 9.2 | |
| 32색으로 줄인 뒤 | 41.7% | 115.4 | 0.20 (0.12~1.02) |

색을 줄이면 나빠진다. 흐린 경계는 원래 이웃끼리 조금씩 바뀌는 비탈이라 잡음 문턱(`GridDetector` `NoiseFloor = 14`)에 걸리지 않는데, 줄이면 그 비탈이 칸 안에서 큰 계단 여러 개가 되어 가짜 경계가 생긴다. 색이 많을수록 계단이 많아 칸을 진짜의 ⅕로 잡는다. Snapper는 밝기 차의 합을 보므로 계단이 생겨도 합이 같지만, Chickxel은 문턱을 넘는 경계를 세므로 반대로 작용한다.

## 3. 자동 최적화에 이미 들어 있는지

두 기준(외곽선 맞추기 `OptimizeParam.OutlineFit`, 칸 크기 기준 `OptimizeParam.GridSource`)은 이미 자동 최적화 항목이고, 기본 최적화 프리셋 중 체크된 넷(같은 색상 계열·OKLab·원본 충실·깔끔한 도트)은 칸 다섯(배경·격자·칸 색·팔레트·정리)을 모두 최적화하므로 두 항목을 바꿔 본다.

시작 = 기본 설정, 200번:

| 그림 | 기본 항목(칸 크기·색 수·칸 색·정리·팔레트 색) | + 외곽선 맞추기 | + 외곽선 맞추기 + 칸 크기 기준 |
|---|---|---|---|
| ai-walk-sample | 67.5 (16.00px) | 67.5 (16.00px) | 67.5 (16.00px) |
| ai-spear-boy-sticker | 72.8 (22.34) | 73.8 (23.16) | 73.8 (23.16) |
| ai-sword-boy | 79.3 (20.17) | 73.4 (20.77) | 73.4 (20.77) |
| ai-mage | 74.9 (14.24) | 72.5 (13.94) | 72.5 (13.94) |
| 나머지 5장 | | ±0.6 | ±0.6 |

'원본 충실' 프리셋 그대로(모든 항목, 3000번·60초), 칸 크기마다 가장 높은 점수:

| 그림 | 1위 | 칸 크기별 최고 점수 |
|---|---|---|
| ai-walk-sample | 75.8 (15.32px, 크기를 줄여서) | 7px 61.5 · 11px 65.7 · 14px 75.6 · 15px 75.8 · 18px 59.4 |
| ai-spear-boy-sticker | 85.1 (21.60px) | 21px 84.5 · 22px 85.1 · 25px 73.4 · 28px 57.8 |
| ai-sword-boy | 89.5 (20.67px) | 18px 87.7 · 21px 89.5 · 24px 80.9 |
| ai-mage | 87.9 (13.94px) | 13px 87.6 · 14px 87.9 · 17px 57.1 |

- 최적화는 걷기에서 7px도 해 봤지만 15px보다 14점 낮게 매겼다. 두 항목은 이미 바꿔 보고 있고, 작은 칸을 고르지 않는 것은 점수(블록 반복도·외곽선 1px) 때문이다.
- 기본 항목에 외곽선 맞추기를 더하면 같은 예산에서 칼 소년 −5.9점, 마법사 −2.4점: 바꿔 볼 것이 늘어 예산이 흩어진다.

## 4. 덤: 빨간 목도리·칼날 회색이 사라지는 곳

Snapper 결과에는 있고 Chickxel 기본 결과에서 사라진 빨간 목도리(걷기)와 칼날 회색(칼 소년)은 격자가 아니라 팔레트 단계에서 사라진다. 같은 칸(15.95px, 20.76px)에서:

| 그림 | 기본(OKLCH 묶기) | 원래 색 유지 | k-평균 16색 |
|---|---|---|---|
| ai-walk-sample | 60.5점, 13색, 목도리 없음 | 54.9점, 765색, 목도리 있음 | 67.6점, 16색, 목도리 있음 |
| ai-sword-boy | 67.7점, 6색, 칼날 살구색 | 77.3점, 335색, 칼날 회색 | 81.4점, 16색, 칼날 회색 |

## 결론과 남은 문제

- 1번(분석 전 색 줄이기): 넣지 않는다. 합성 그림에서 크기 맞음이 100% → 92.5%(16색)·41.7%(32색)로 떨어지고, AI 표본에서는 칸 크기가 거의 바뀌지 않는다.
- 2번(색 경계 기준): 새로 넣을 것이 없다. 외곽선 맞추기·칸 크기 기준은 이미 자동 최적화 항목이고 체크된 기본 최적화 프리셋이 바꿔 본다. 기본 항목에 더하면 같은 예산에서 오히려 낮았다. 더 작은 칸을 고르게 하려면 항목이 아니라 점수 기준(블록 반복도 0.65 문턱, 외곽선 1px 비중)을 바꿔야 한다.
- 남은 문제: 기본 설정(OKLCH 묶기)이 작지만 눈에 띄는 색(빨간 목도리, 칼날 회색)을 지우고, k-평균 16색이 두 그림에서 점수·모양 모두 낫다. 기본 팔레트 방식이나 '다른 색상 지키기' 문턱(채도 0.04·넓이 4칸·색상 20도)을 다시 볼 만하다.
