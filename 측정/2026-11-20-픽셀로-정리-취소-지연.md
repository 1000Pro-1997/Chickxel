# 픽셀로 정리: 여러 프레임 자동 최적화의 취소 지연

## 왜

120프레임 AI 그림을 픽셀로 정리하며 자동 최적화를 돌리다 취소를 누르면 바로 멈추지 않는다는 보고. 취소는 시도 사이와 `Pixelator.RunOnce`의 몇 단계 사이에서만 확인했고, 격자 맞추기·팔레트·충실도 재기(`Measure`) 안에서는 확인하지 않았다. 그래서 그때 돌던 시도들이 끝까지 돌아야 멈췄다.

## 환경

- Windows 11(10.0.26200), Intel Core i5-13400F(16스레드), .NET SDK 10.0.300, Release
- 시험할 때 다른 앱(브라우저·실행 중인 Chickxel)이 함께 돌아 시간이 크게 흔들림

## 방법

- `tests/Chickxel.Core.Tests`에 잠깐 넣은 시험(저장소에는 넣지 않음)으로 쟀다.
- 그림: `tests/fixtures/ai-girl-bg.png`(162×166)를 2160×2048 시트의 15×8 칸(칸 144×256)에 프레임마다 조금씩 옮겨 120장 붙임
- 설정: 격자 나누기 15×8, 원본 프레임 120(`SourceFrames`), 고정 크기 128×215, 나머지는 기본
- 자동 최적화: `OptimizeParam.SelectAll`, 시도 10000번, 시간 10분 → 15초(또는 40초) 뒤 취소, 취소부터 `PixelateOptimizer.Run`이 돌아올 때까지 잼
- 고치기 전(HEAD)과 고친 뒤를 번갈아 여러 번 돌림

## 결과

| | 취소 지연 | 설정 그대로 한 번 정리(단독) |
|---|---|---|
| 고치기 전 | 6.0~12.0초(4번) | 3.8~10.9초 |
| 고친 뒤 | 0.09~1.5초(6번) | 5.4~14.9초 |

- 단독 한 번 정리 시간은 두 쪽 범위가 겹친다. 첫 번째 실행(JIT 전)과 다른 앱 부하 때문에 흔들린 것이다. 확인 넣는 곳은 프레임마다·칸 1024개마다 한 번이라 비용이 거의 없다.
- 병렬 시도는 15개 가까이 함께 돌아 한 시도가 25~35초 걸렸다. 고치기 전에는 그동안 돌던 시도가 끝날 때까지 기다렸다.

## 고친 것

`Pixelator.RunOnce` 안에서 취소를 확인하는 곳을 늘렸다.
- 격자 맞추기·고정 크기 다시 나누기: 프레임마다
- 팔레트: 히스토그램 뒤, 팔레트를 만든 뒤, 칸 그림에 색 입히기는 프레임마다
- 정리: 프레임마다
- 충실도 재기(`Measure`): 프레임마다, 칸끼리 색 차이는 칸 1024개마다, 외톨이 세기는 프레임마다

## 남은 문제

- 배경 지우기·프레임 나누기를 바꿔 보는 시도는 원본을 다시 준비한다(`PixelateSource.Prepare`). 이 준비 안에서는 취소를 확인하지 않는다. 단독으로 0.3~0.7초라 그대로 두었다.
- 한 단계(예: 공유 팔레트 k-평균 한 번) 안에서는 여전히 끝까지 돈다. 부하가 크면 1초 남짓 걸릴 수 있다.
