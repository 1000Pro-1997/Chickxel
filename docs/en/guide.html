Common controls

Basic controls that work the same everywhere in the app.

Changing number fields

Size, coordinates, FPS, zoom, effect strength — every number field in the app supports the same three methods. Use whichever fits the moment.

  1. Click and typeClick the field and type a number. Clicking elsewhere confirms it.
  2. Drag left or rightGrab the field and drag sideways to change the value. Shift is 10× slower, Ctrl steps by 10. When you hit the edge of the screen, the cursor wraps around so you can keep dragging.
  3. Right-click and pickRight-click the field for a list of common and recent values. The current value is marked with a dot.

Drawing with AI

Claude Code or Codex on your own computer drives Chickxel with your own account (no API key). Say something like "draw a 32×32 wooden barrel" and it draws right into the open image.

  1. Open AI chatCtrl+L or the AI button in the top bar. Pick the Claude or Codex tab and log in once.
  2. Describe what you wantInclude size, subject and colors for the best results. Progress shows while it draws.
  3. Undo if you don't like itEach reply is one undo step. Use Ctrl+Z or "Undo this step" under the reply.

In our testing, Codex's Astra model (gpt-6-astra) drew the best results. See the AI chat chapter for details.

Pixelate

Turn AI-generated art or any image into clean pixel art.

Comparing cell by cell in the enlarged view

See the cell grid Chickxel actually used laid over the source, then check the result and the source side by side at the same size, one cell at a time.

  1. Show gridThe source view draws the cell borders the selected candidate used, so you can see right away whether the cells line up with the color blocks.
  2. EnlargeClick the result or the source in the large preview to open both at the same size.
  3. Inspect a cellClick a result pixel or a source cell to highlight where that color is used and which result pixel the source cell became.

Turning images into pixel art

Drop in an image and Chickxel finds the pixel size, snaps to the grid, removes the background and reduces the colors. It builds one candidate per preset and shows them side by side with their scores, so you just pick the one you like.

  1. Add an imageOpen AI > Pixelate AI image… and drag an image in or paste it with Ctrl+V.
  2. Pick a candidateOne candidate is built per checked preset, each shown with its score. The enlarged view compares the result and the source cell by cell.
  3. InsertInsert it as a new layer in the current document or in a new tab.

Settings and scoring are covered in the Pixelate AI images chapter.

Removing and adding colors

Check each color in the result, remove the ones you don't need, and pick missing ones from the source.

  1. Show where a color is usedClick a color swatch or a result pixel to highlight where that color is used.
  2. Remove a colorRight-click to remove it; its pixels take the nearest remaining color. Right-click again or use Restore all to bring it back.
  3. Add a colorClick the + at the end of the swatches, then click a source cell to add that color to the result as a pinned color.

Animation effects

Layer effects on without touching your pixels to create motion.

Stacking effects

Stack as many effects as you like — outline, shadow, shine, shake, explosion, fade and more. They're layered on without changing your pixels, so you can toggle or reorder them anytime, and saving bakes the result into the sheet.

  1. Open the effects windowRight-click the layer name in the timeline and choose Effects….
  2. Pick and stack effectsDouble-click a live-preview effect card or drag it into the list. Effects stack from the top of the list down, with a before/after preview.
  3. Set the frame rangeDrag in the frame strip under the preview to set each effect's range. Frame extension can add the animation frames for you.

Effect types and settings are covered in Layer effects.

Effect clipping

Turn on Clip to effect above under Apply to in an effect's settings, and that effect applies only to the pixels the effect above it produced — not to the original sprite. For example, clip a color overlay under an outline to paint just the outline with a gradient while the sprite stays untouched.

  1. Add a base effectStart with an effect that creates new pixels, such as outline or reflection.
  2. Add an effect right below itPut the effect you want on top of it — color overlay, shine, afterimage and so on — directly below the base effect.
  3. Turn on Clip to effect aboveIn the lower effect's settings, turn on Apply to > Clip to effect above. It shows indented in the list and the timeline.

Save a base effect together with its clipped effects in the Custom tab of the effect types to reuse it later.

Using palettes

Import palettes and fit your sprite's colors to them.

Importing Lospec palettes

Browse the Lospec palette list — palettes made by pixel artists around the world — right inside the app and import them. Each palette comes with example art drawn in its colors.

  1. Open Palette webChoose Palette web (Lospec)… from the menu button on a palette header.
  2. BrowseSort by popular or newest and filter by color count or tag (e.g. gameboy, pico8). Type a palette name to find it right away.
  3. ImportUse as palette replaces it, or Add to current palette adds only the colors that are missing. You can keep several palettes stacked.
  4. FavoritesClick the star on a palette you like to add it to your favorites. Choose Favorites in the sort box to browse and import them — example art included — even without internet.

Reference site: lospec.com/palette-list (internet required — favorites work offline; palette copyrights belong to their authors)

Recoloring with a palette

Replace every color in a sprite with the nearest color in a chosen palette, in one step. Try the same sprite in a different mood, or bring a whole game onto one palette.

  1. Pick a paletteOpen the palette with the colors you want — palettes imported from Lospec work too.
  2. Open Convert to palette colorsChoose Convert to palette colors… from that palette's menu button.
  3. Choose a target and dithering, then OKPick the current cel, all frames of the current layer, or all layers and frames, and optionally turn on dithering (Bayer 4×4). Dithering is used only where the blend the eye sees of two palette colors is closer to the source. Check the before/after preview; one undo reverts it.

Skins

Draw several looks per part and swap them.

Managing skins

Split a character into parts like head, body and arms, draw several skins for each, and swap them with one click. Cells left empty in other skins inherit the first skin's art, so you only redraw the parts that change.

  1. Create a group and partsSplit the character with a new group (Ctrl+Shift+N) and new parts (Shift+P).
  2. Add skins and drawAdd skins from the skin chip in the timeline or the Skin manager, and draw only the parts that change.
  3. SwapPick a skin from the outfit row under the preview or the skin chip, or jump with Alt+[ / Alt+].

Skins can be exported as separate files per skin or as a Unity Sprite Library. See Part (group) layers · skins for details.

Tile and item skins

Skins aren't only for outfits. Put a tile and the items that drop from it in one group as parts, and make each material — wood, dirt, ore — a skin. Every variant then lives in one file at the same size and position.

  1. Group them as partsPut the block tile and its items in one group as parts (e.g. tile, item_1, item_2, item_3).
  2. One skin per materialMake a skin per material like plank, dirt or ore, and every part in the group switches together. The Skin manager shows each part's look at a glance.
  3. Export in one goSaving exports per-skin sheets or a Unity Sprite Library, so the game only needs to switch the skin name.

Unity integration

Values you set in Chickxel carry straight into Unity.

Pivot sync

The pivot you set in Chickxel is written into the Unity .meta sprite pivot when you save. No adjusting in Unity — the anchor you want, like a character's feet or a weapon's grip, lines up the same in the game.

  1. Pick the Pivot tool (K)Drag the anchor on the canvas, or use the 9-direction buttons and X/Y fields in the tool settings.
  2. Choose the targetWith a part selected, that part's pivot changes; otherwise the project default pivot (all frames). Turn on Current frame only to set it for one frame.
  3. Save to update UnitySaving writes the pivot into the .meta alongside the PNG sheet. Transform (Ctrl+T) also starts rotating around this pivot.

Export

In the Ctrl+E export window, set the sheet layout, how skins are packed, whether to split files, and the Unity import settings. Even when it exports several files, one .chickxel keeps them together.

  1. Open the export windowCtrl+E. A preview of the sheets and the list of files to be written appear on the right.
  2. Set layout, skins and splittingChoose cell layout and spacing, whether to pack all skins in one image or one file per skin, and whether to split by tag, part or skin. Unity Sprite Library and import settings (.meta) are set here too, and you can save favorite settings as presets.
  3. Save to export them togetherEvery save rewrites the PNGs and .meta with these settings. The file browser hides the exported PNGs and shows the single .chickxel; hover to see the exported file names, and searching by those names finds it too.

Getting started

Chickxel is a pixel art editor for games (especially Unity 2D). Frames, layers and tags (animations) are stored in a .chickxel project, and saving also produces a PNG sprite sheet and a Unity .meta. You don't need to install .NET or anything else.

Installing from the terminal

macOS — paste this into Terminal to download the file for your chip, install it to /Applications/Chickxel.app and launch it.

ARCH=$(uname -m); [ "$ARCH" = x86_64 ] && ARCH=x64
curl -fL -o /tmp/Chickxel.zip "https://github.com/1000Pro-1997/Chickxel/releases/latest/download/Chickxel-macos-$ARCH.zip" \
  && rm -rf /Applications/Chickxel.app && ditto -x -k /tmp/Chickxel.zip /Applications \
  && xattr -dr com.apple.quarantine /Applications/Chickxel.app; rm -f /tmp/Chickxel.zip; open /Applications/Chickxel.app

Windows — paste this into PowerShell to install to %LOCALAPPDATA%\Programs\Chickxel, create a Start menu shortcut and launch it.

$d = "$env:LOCALAPPDATA\Programs\Chickxel"; $z = "$env:TEMP\Chickxel.zip"; $x = "$env:TEMP\Chickxel-x"
Invoke-WebRequest "https://github.com/1000Pro-1997/Chickxel/releases/latest/download/Chickxel-windows-x64.zip" -OutFile $z
Expand-Archive $z $x -Force; New-Item -ItemType Directory -Force $d | Out-Null
Copy-Item "$x\Chickxel-windows-x64\Chickxel.exe" $d -Force; Unblock-File "$d\Chickxel.exe"; Remove-Item $z, $x -Recurse -Force
$s = (New-Object -ComObject WScript.Shell).CreateShortcut("$env:APPDATA\Microsoft\Windows\Start Menu\Programs\Chickxel.lnk"); $s.TargetPath = "$d\Chickxel.exe"; $s.Save()
Start-Process "$d\Chickxel.exe"

Both methods install to a location your account can write to, so later updates happen automatically inside the app.

First launch

  • The app isn't developer-signed, so you'll see a warning the first time.
    • Windows "Windows protected your PC": More info → Run anyway.
    • macOS "unidentified developer": right-click → Open on Chickxel.app. If that doesn't work, go to System Settings → Privacy & Security → Open Anyway.
  • Choose a folder (① Open folder…, ② recent folders) or Unity project on the start screen and the ③ file browser on the left shows that folder's images. ④ Projects registered in Unity Hub can be opened directly from the list.
  • On first launch the display language follows your computer's language (Korean or English; English if there's no match). See Language to change it.

On macOS, read Ctrl in this guide as ⌘ (Command) (e.g. ⌘+S to save). The eyedropper is ⌥+click, and holding ⌘ switches temporarily to the Move tool. Menus and tooltips also show ⌘.

Updates

Chickxel checks for a new version every time it starts. If one is available, the update dialog opens and an ① Update button appears in the top bar.

  • ② Update now: downloads and verifies the file for your OS, then closes the app, replaces it with the new version and restarts. You're asked about unsaved work first, and if anything fails the previous version stays as it is.
  • ③ Later reminds you on the next launch; ④ Don't show until the next update skips that version.
  • The dialog shows ⑤ the new and current versions and ⑥ the changes between your version and the new one.
  • Check manually any time with ⑦ Help > Check for updates…, and ⑧ turn off automatic checks in Edit > Preferences… > General.

Network and privacy

There are no accounts, analytics or ads, and your images and files are never sent anywhere. The network is used only in these cases:

  • ① Check for updates: asks GitHub for the latest version (can be turned off).
  • Palette web (Lospec): downloads palette lists and sample images only when you open that window. Favorite palettes are stored only on your computer.
  • AI chat: only while you use that window, the Claude Code or Codex CLI installed on your computer connects to Anthropic or OpenAI with your login.

Toolbar

The vertical bar on the far left. Hover an icon to see its shortcut in the tooltip.

  • The ① folder button at the top collapses and expands the file browser (F8).

File browser

It has ① a folder tree, ② a thumbnail list of .chickxel and PNG files, ③ search, and ④ an option to include subfolders; changes to files in the folder are picked up automatically.   • ⑨ Right-click menu: new project, merge, rename, show in Explorer/Finder, select image folder, delete, delete .chickxel files only, restore last deleted, view app trash.

Unsaved changes (red dot)

Every open document lives in a document tab above the canvas, and switching tabs never asks you to save. A document with unsaved changes gets a ⑦ red dot in the top-left of its thumbnail (and next to its tab title); clicking a file that's already open goes to its tab. The status bar shows "N unsaved files".

  • Renaming a dotted file keeps track of it; sending it to the trash keeps the tab and marks it modified (saving recreates the file).
  • If the file changes outside the app, the current tab asks whether to reload; another tab only notifies you when it has unsaved changes (otherwise it reloads when you select it).
  • Only closing the tab of a document with unsaved changes asks Save / Don't save / Cancel.

Deleting and the app trash

  • Deleted files (Delete, multiple allowed) and originals removed by merging go to the app's own trash without asking (including their PNG and .meta files).
  • Press Ctrl+Z in the file list to restore the last deletion to its original place.

Palette

The ① primary/secondary colors are at the top (the secondary defaults to transparent), and below them you can stack ② multiple palettes (DB32 to begin with). ③ New palette at the bottom adds an empty one.

  • ④ Each palette's header has a collapse arrow, its name (double-click to rename), the color count and a menu button.
  • ⑧ Menu actions apply to that palette: add current color, remove primary color, sort by hue, load .hex/.gpl, palette web (Lospec), save .hex, create from image, convert to palette colors, rename, move up, move down, clear, delete.
  • The palette you last clicked or edited is the active palette (⑤ blue line under the header). Palette features in the Edit menu and the AI palette tools use the active palette.
  • The swatch matching the primary color has ⑥ a white border, and the one matching the secondary color ⑦ a blue border. The transparent swatch only appears at the start of the first palette.
  • The palette list (names, colors, collapsed state, order) is saved in the settings and kept next time.

Convert to palette colors

Replaces the colors in the image with the nearest colors in the palette. ⑨ Choose the target from current cel (only inside the selection, if any), all frames of the current layer or all layers and frames (locked layers are skipped), and ⑩ dithering from none (default) or ordered dithering (Bayer 4×4). Dithering mixes two palette colors in light intensity (linear light) and compares the mix with the source in OKLab to set the ratio (e.g. a half black, half white pattern stands for sRGB 188 gray); it is used only when the mix is still closer to the source than the nearest single color after adding how visible the pattern is (lightness difference counts fully, hue and chroma differences half). Colors within a just-noticeable difference (OKLab 0.02) of a palette color are not dithered. ⑪ A before/after preview and ⑫ the change in color count are shown; alpha is kept and fully transparent pixels are left alone. It's a single undo step.

Palette web (Lospec)

Browse the lospec.com palette list inside the app (internet required).

  • Filter by sort order (popular, downloads, newest, name), color count and tag (e.g. gameboy, pico8). Entering a palette name in the tag field shows that palette at the top.
  • Selecting a palette shows its colors along with example art made with it.
  • Use as palette (replaces the current palette; same as double-click), Add to current palette (skips duplicate colors), Save as .hex, View on Lospec.
  • Favorites: click the star at the right of a list row or next to the selected palette's name to add or remove it. Favorite palettes, including their example art, are kept on your computer (<settings folder>/Chickxel/Lospec).
  • Choose Favorites in the sort box to show only your favorites, most recently added first (no internet needed). The color count and tag/name fields still filter them. If Lospec can't be reached, use View favorites next to the error.
  • The last sort you chose is kept the next time you open the window.

Canvas

Shows the current frame (all visible layers combined) and draws onto the current layer's cel.

  • Selecting a part layer shows ① only that part at its own size, with ② the rest of the frame shown semi-transparently so you can line things up. Selecting a group layer lets you drag parts to arrange them (see Part (group) layers).
  • Supports 1–64× integer zoom, ③ checkerboard background, ④ pixel/⑤ tile grids, ⑩ tiled mode (for seamless patterns), ⑥ symmetry guides, ⑦ pivot, ⑧ selection and ⑨ onion skin.
  • Hold H to peek at the previous frame.
  • Even with heavy effects on large images or many frames, the window doesn't freeze while effects compute. When a frame takes a while, the canvas gets a gray semi-transparent veil with the partial result showing underneath as it is computed, plus a loading icon and progress bar at the top right of the image area. The veil lifts all at once when the frame is done. If computing falls behind while you draw, new strokes appear right away without effects and the effects catch up afterwards. Light images update immediately without a veil.

Layer effects

Layer effects are non-destructive: they're applied only when displayed, without changing cel pixels. They automatically apply to anything you draw later and are all rendered per pixel (no blur or anti-aliasing).

  • Right-click a layer name and choose ① Effects… to open the effects dialog. Layers with effects show ② fx on the right of the name.
  • Normal layers and parts apply effects to their cel; groups apply them to the combined shape of their parts. For example, a group outline is drawn as a single line around the whole character.
  • Effects stack from the top of the list down (outline → shadow means the shadow includes the outline) and can be toggled individually.
  • Each effect has a frame range ("All frames" or a start–end frame).

Effect colors and clipping

  • Clicking a ③ color swatch opens a popup with the same square, honeycomb, color wheel and slider modes as the main color editor, plus the palette, recent colors and an eyedropper; the canvas updates as you pick.

Effect rows in the timeline

Deleting frames in the effects dialog

The dashed trash cell after the last cell of the ⑫ frame strip is the ㉑ delete cell. Grab it and drag left: the cells from there to the last cell get a red veil and border, and releasing marks those frames for deletion. The first frame can't be deleted.

  • ㉒ The trash cell shows how many frames you deleted last, in red. Click the trash cell without dragging to bring back only that last deletion (earlier deletions can't be restored).
  • While frames are marked for deletion, the preview and frame strip show the order after deletion, and effects whose range lies only in the deleted frames appear turned off (they are removed when you click OK).
  • If you then drag a range end past the last cell or raise the frame count with ⑭ Extend frames, the deleted frames are discarded (no longer restorable) and new frames are added after the remaining ones.
  • The frames are removed from the project when you click OK or Apply permanently. This is one undo step together with the effect changes, and effect ranges and tags shrink just as when you delete frames in the timeline. Cancel deletes nothing.

Applying permanently and where effects show

  • Apply effect permanently bakes the effect into the cel pixels and removes it from the list (you can then edit it like any drawing). Enabled effects above the selected one are baked too, so the result looks exactly as it did. Group effects and locked layers can't be applied permanently. While baking, a Baking effects progress overlay (percentage) appears and closes when it finishes (both in the effects dialog and from the timeline effect box's right-click menu).
  • Duplicating a layer also copies its effects, and Merge down bakes the upper layer's effects.
  • Effects are shown on the canvas, preview, frame sheets and thumbnails. The drawing view for a selected part shows the plain image without effects.
  • The part atlas includes only the part's own effects; spreading effects such as outlines or shadows make the sprite wider by that amount (the pivot is shifted so it points at the same spot).
  • Effects this version doesn't know (for example, ones added in a newer Chickxel) are not thrown away. Effect recipes

An effect recipe is a named bundle of several effects with their values and clipping relationships. Insert it into other layers or projects in one go from the Custom tab of the effects dialog; with parameters, a few values adjust the whole bundle.

  • Build an effect list in the effects dialog and click Save all effects to save it as a ② personal recipe. ③ Recipes and ④ script effects from enabled packages show on the same tab. Double-click a tile or drag it into the effect list.
  • Tile right-click menu: personal recipes have Rename, Edit parameters, Delete and Show in Asset Manager; recipes from packages only have Show in Asset Manager. To change a package recipe, copy it to your personal assets in the Asset Manager.
  • ① Asset Manager opens the Asset Manager filtered to effects. Inserted recipes are copied by value, so they stay in the project and remain editable even if you turn off or delete the original recipe or package.

Setting parameters

  1. Right-click a personal recipe on the Custom tab and choose Edit parameters (the personal recipe details in the Asset Manager have the same button).
  2. Click Add to create a parameter in the ⑤ list and give it a ⑥ Name.
  3. Under ⑦ Linked settings, check the settings this value changes together. Each recipe effect lists the settings it can expose as "number. effect name · setting key (kind)". The first link sets the parameter's kind and default (that setting's current value); settings of another kind and settings already linked to another parameter are disabled.
  4. Depending on the kind, set ⑧ the Default, the Range for integers or the Choices for choices, then click OK.

Invalid links or ranges are listed as problems at the bottom of the window, and OK stays off until they are fixed. The recipe details in the Asset Manager list the number of parameters with their names and kinds.

Using a parameter recipe

  • ⑨ A recipe with parameters appears in the effect list as one row, "recipe name · recipe, N effects" (with an expand arrow and a group icon).
  • ⑩ Selecting that row shows only the recipe name, source and parameters in the settings; changing a value updates every linked effect setting together.
  • ⑪ Show effects lists the effects inside under the group row so you can edit them one by one, and Hide effects folds them again. Ungroup turns them into ordinary effects with their current values (the parameters go away).
  • A collapsed group moves, drags, deletes and applies permanently as one unit.

Script effects

A script effect is a layer effect you write yourself in JavaScript. Declare effect({ name, settings, render(img, ctx, s) { … } }) and the settings panel is built for you; previews, the timeline and exports draw it exactly like built-in effects. Scripts run in an isolated engine with no file or network access, and the source is saved inside the project file.

  • ① The Script effects group at the bottom of the Built-in tab: New script adds an effect from the light sweep example and opens the editor. Open JS file… adds a .js file as an effect; if the source has errors, it is not added and the editor shows the errors.
  • With a script effect selected, the top of the settings shows ② the declared name, the author, the first 12 characters of the source hash and a status line (time per frame in the current preview, or an error). ③ Edit script… opens the editor, and Open JS file… replaces this effect's source with a file (settings with the same key keep their values).
  • ④ Save as asset: saves the source as a personal script asset you can reuse from the Custom tab and the Asset Manager and export in a package. Only scripts allowed to run can be saved, and saving the same source twice keeps one copy.
  • ⑤ The settings come from the declared settings: integer and number = slider with number field, on/off = checkbox, color = color swatch, choice = list. A script declared as animated also gets Speed and Loop, like the built-in animated effects.

Script editor

  • Edit the source in the ⑦ monospace text box, following ⑥ the declaration hint at the top. ⑨ Apply (Ctrl+Enter) shows the result in the effects dialog and on the canvas right away.
  • ⑧ Syntax and declaration errors are listed as "Line n, column m: …"; click one to move the cursor there. The line after them shows the run status in the current preview (time per frame, or a run error).
  • Applying an edited source switches the effect to the new source; old sources no longer used are dropped from the project when you save.

Allowing scripts to run

Opening a project with scripts you haven't seen before (with Open, drag and drop and so on) shows the Run script effects? window. ⑩ Each script has a checkbox (on at first), its name, author and full hash; ⑪ Run runs only the checked ones and Don't run runs none.

  • Your choice is remembered on this computer per source hash. Effects that don't run aren't drawn and stay in the project as they are; you can allow them later with Allow to run in the effects dialog settings.
  • Scripts written or imported on this computer and scripts saved as personal assets run right away without asking. Scripts from packages (file or online) aren't drawn when inserted; selecting the effect shows the not-running status and an Allow to run button, which draws it immediately.

Saving

Saving the .chickxel with Ctrl+S (① File > Save (+ export sheets)) also exports the image and .meta, depending on your settings, and ② the status bar shows the result. Meanwhile drawing, shortcuts and file drops are ignored and other windows (such as the AI chat) are disabled; AI tool calls run once it finishes. Closing the window then closes it after the save completes.

Autosave

On by default. After 3 seconds without edits, it saves without asking, just like Ctrl+S (including export), and shows Autosaved in ① the status bar.

  • It waits while you're drawing, dragging, transforming or while the AI is working.
  • It only saves files that already have a .chickxel on disk. New projects and imported PNGs must be saved manually once.
  • Autosave writes in the background without the overlay, so you can keep editing while it saves; changes made meanwhile go into the next autosave. Only very large documents (over about 768 MB of pixels) show the overlay during autosave too. Saving, exporting, Revert to saved or closing the window during an autosave continues once the autosave finishes.
  • ② Turn it on/off and change ③ the wait time (1–600 seconds) in Preferences > General.

Revert to saved

① The button at the bottom of the toolbar or ② File > Revert to saved discards unsaved changes after ③ confirmation and reopens the file. The current layer, frame and zoom stay the same. The revert itself can't be undone.

Undo history that survives closing

On by default: even after closing a file or quitting the app, you can keep using undo and redo when you reopen it. History is kept only up to the saved state; changes discarded with "Don't save" aren't kept. The history is stored separately in the app settings folder, not in the .chickxel.

① Turning it on/off, ② retention period (default 30 days), ③ maximum size (default 500 MB) and ④ Clear all history are in Preferences > General.

Opening (importing) PNGs

Opening a PNG imports it as a project. If a .chickxel with the same name exists, or a project in the same folder exports that PNG, that project opens instead.

  • If the meta contains cell information and the cells differ in size, it's imported as parts (one group + one part per cell).
  • If all cells are the same size, you're asked to choose "① As parts / ② As animation frames".
  • Sheets without cell information can be split with ③ Frame·Layer > Split into frames by grid: ④ pick the method and split by ⑤ cell size, ⑥ cell count or ⑦ automatically (by blobs).

Opening images, animations and videos

① File > Open (.chickxel · image · GIF · video)… (Ctrl+O) lets you pick several files at once and opens each in ② its own tab. Images other than PNG (JPG, BMP, GIF, WebP, ICO, animated PNG) become a new document: canvas = image size, ③ one layer named after the file, ④ one frame per image frame.

  • Frame durations come from the file (0–10 ms become 100 ms, like browsers). Transparency is kept, and partial GIF/APNG frames with their disposal (restore to background / previous) are composited so every frame is a complete picture. Photos follow their EXIF rotation.
  • Files with more than 300 frames ask ⑤ "Open all / First 300 only / Cancel".
  • There's no .chickxel yet, so the first save asks where to put it. Clicking in the file browser, recent files and dropping on the window open files the same way.
  • Videos (MP4, WebM, MOV, MKV, AVI, …) and AVIF/HEIC images need ffmpeg (not included with Chickxel and never downloaded automatically — ffmpeg.org, or winget install Gyan.FFmpeg on Windows). It's found automatically on PATH or in common install locations; otherwise choose ⑦ the executable in ⑥ Edit > Preferences… > Video (ffmpeg) with ⑧ Browse….
  • Opening a video first shows the Import video window: ⑨ range (start–end seconds), ⑩ frames per second (default: the video's, at most 12), ⑪ max frames (default 120), ⑫ size (original / fit long side — turn ⑬ Smooth off to keep pixels crisp), and ⑭ an estimate of frames, size and memory. ⑮ Import shows a progress window you can cancel; each frame lasts 1000 ÷ frames per second.

Dropping images onto the canvas

Drag images (PNG, JPG, BMP, GIF, WebP, APNG, …) or videos from Explorer/Finder or the file browser onto the canvas and each file becomes a new layer. While dragging, the canvas edge lights up and ① a dashed rectangle shows where the image will go.

  • ② The new layer is added above the current layer and named after the file (without the extension). Several files stack in drop order, and the last one ends up on top as the current layer. With a part or group selected, it goes above that group, like Add layer.
  • The image is placed with the pixel you dropped on at its center, in the current frame, with its colors unchanged; anything outside the canvas is cut off. An image larger than the canvas is centered on the canvas and you're told it was cut — to keep all of it, enlarge the canvas first in Canvas size mode.
  • Animated GIF, WebP and APNG files and videos (after the Import video window) go into one layer starting at the current frame; if there aren't enough frames, new ones are added at the end (with the image's or video's frame durations).
  • The whole drop is a single undo step (Drop image).
  • Dropping outside the canvas (file list, start screen, tab strip, panels) doesn't add layers — each file opens in its own tab. Dropping only a .chickxel on the canvas opens it in a new tab too.
  • A single-frame image goes straight into ③ transform mode (the last one if you drop several; ④ the status bar explains the keys): the whole uncropped image is held, so move or resize it and press Enter to apply — parts outside the canvas are cut only then — or Esc to keep it as inserted (insert and transform are two undo steps). Multi-frame images are inserted without transform mode.

Cleaning up old outputs and renaming files

Pixelate AI images

AI-generated "pixel-look" images have inconsistent pixel sizes (e.g. 7–9 px), blurred edges, JPEG noise and hundreds of colors. This window turns such images (with a solid or transparent background, or sprite sheets with several frames) into clean pixel art.

Opening

  • ① AI > Pixelate AI image…: opens an empty window. As ② the message in the middle says, drop an image on it, paste one with Ctrl+V, or ③ Browse… for a file (PNG, JPG, BMP, GIF, WebP). ④ Apply and ⑤ auto optimize stay off until there's a source.
  • ⑥ AI > Pixelate current layer… (right below Pixelate AI image…): uses the current layer as the source. If several frames have content, they're joined side by side and split as a grid, one cell per frame.
  • In the file browser, right-click ⑦ an image file > ⑧ Pixelate AI image…: opens with that file as the source.

Loading or replacing the source: drop an image file anywhere on the window (the first image if several), press Ctrl+V outside text boxes (an image file copied in Explorer or an image file path as text first, otherwise the clipboard image), or Browse… (starting in the folder selected in the main window's file browser). With a source loaded, ⑨ Replace source in the status row, or another drop or paste, swaps it: candidates, preview and optimizer results are cleared, the frame split is applied again to the new image and everything is built again. The window can stay open while you do other things, such as using the AI chat.

Background and frames

  • ② Background: Keep · Auto (the most common border color; if the border is mostly transparent, the existing alpha is used) · Pick color. Tolerance (RGB distance, Auto from border noise), Only background connected to the border (flood fill from the border, so near-black outlines touching a black background and eyes are kept), use existing transparency, alpha threshold, speck size (small detached specks are removed).
  • ③ Frames: Single · Auto (split by fully empty rows/columns; small detached pieces such as effects are merged into the nearest frame within a distance; sprites that touch or overlap sideways, so no empty column separates them, end up as one piece much wider than the others and are parted at the thinnest vertical line) · Grid (columns × rows — pixels aren't cut along the cell lines but assigned by connected blob, so hands and feet crossing a cell line don't leave fragments at the edge of the neighbouring frame; two touching sprites are parted at the thinnest spot near the cell line). Align bottom-center (default) · center · keep offsets; all frames get the same canvas size. Press Apply frame split to split again with the new values (candidates are rebuilt too). You can also drag the frame boundaries directly in the source view (Source and preview).

Pixel grid and output size

  • ④ Pixel grid: Pixel size from chooses Auto (best edge match) · Outline thickness · Color edges · Block edges (used when cleanup's Fit outline to 1 px is Thin outline only, Redraw as vector or Off; disabled with By shrinking). Pixel sizes from 3 to 256 px are measured, so blocks enlarged past 100 px are found at their real size too. Color edges estimates the pixel size as a decimal from run lengths between color changes, tolerant to jitter and preferring the finer of two harmonics. Outline thickness measures the dark band touching transparency across many horizontal and vertical sections and picks the size at which the outline becomes 1 px. Block edges ignores weak texture such as paper grain (only neighbor OKLab differences above the image's noise level count) and picks the spacing at which strong color edges line up within a row (preferring the full block even when half blocks are mixed in), and the cell lines follow those strong edges too. Auto uses block edges when the block spacing is clear, otherwise fits cell lines for each of the three values and picks the one that best matches the source's strong edges (the match has the chance level removed — what the same edges give after shuffling their positions — because larger cells have more room to land on an edge by chance; on a near tie: outline, then block edges, then color edges, and a value that is 2× or 3× the chosen one and matches about as well wins). By shrinking only picks among values within ±12% of the outline thickness (a half-block value would make the outline 2 px) — unless the outline is thinner than a pixel (e.g. a blurred 1-px rim) and a larger value matches clearly better, then it shrinks to that. Clean images with at most 256 colors use the exact integer factor they were enlarged by (2–256), and 1-px pixel art (including flat fills with 1-px outlines) uses 1. Noisy or JPEG images with more than 256 colors are still detected when they are pixel art at original size (1-px cells) or 2× (2-px cells) (the reason reads "{n}px cells of noisy pixel art"). Cell boundaries are then fitted onto real edges even when cells vary 7–9 px. The pixel size and boundaries are always found per frame (output by scale factor or fixed size and refitting use each frame's boundaries too), with a jitter allowance %. Manual takes a pixel size and X/Y offset; Use detected as manual copies the auto result. The detected size, offset and edge fit % are shown, along with the three values, their edge match, the chosen one and why, e.g. "Color edges 5.75px (3%) · outline 24.75px (9%) · block edges 19px (8%) → Outline thickness (edge match 9%)". With By shrinking it shows "By shrinking: only values within ±12% of the {o}px outline are used, shrinking to a {s}px pixel size" (or "the {o}px outline is thinner than a pixel … so it shrinks to {s}px"); with Thin outline only or Redraw as vector, when the outline is about an integer multiple (2× or more) of the pixel size, an "outline is drawn {n} pixels thick…" note is added. Local cell correction (on by default) re-fits the image-wide cell boundaries per band (2 cells by default) to the strong block edges in that band (each boundary within Max shift, 35% of a cell by default; cell widths 70–130% of the original; smooth between neighboring bands) — so images drawn half a cell off in places are followed too. Boundaries are straight inside a band, so cells stay rectangles and the boundaries bend where bands change. Each band counts color edges that continue over several rows, drops short 1–2 px noise and weights high-contrast edges more, so sharp, continuous edges are matched first. When two sharp edges fall within one cell spacing (e.g. two black→skin edges 5 px apart), one cell line can't fit both. It is skipped when the average cell size is below Minimum cell size (px) (default 4 px, 1–16 px).
  • ⑤ Output size: From pixel size · Fit a fixed size (W × H, e.g. 32/48/64, keep aspect, padding) · Scale factor. Auto next to the mode is the same setting as Auto in the bar under the source (off = fit a fixed size, on = the last automatic mode).

Optimize grid fit first at the top of 3. Pixel grid (saved with the preset) makes Clean up and Auto optimize first try only the grid values (pixel size, size jitter, pixel size source and local correction; offset X/Y for a manual grid) to find the grid with the best cell split score, then keep that grid while optimizing the other steps that have Optimize on. The cell split score looks only at the source and the cell boundaries: it is the average of Cell edge fit (higher when the cell lines miss none of the source's strong edges and the lines crossing the sprite lie on source edges — cells smaller or larger than the real ones both score low) and Cell color purity (higher when each cell's interior holds only similar colors). When other steps are optimized too, the grid stage uses up to half of the trial and time budget, and while this is on the Optimize check in the 3. Pixel grid header is disabled (this check takes its place). Preview cells next to it adds a tile of that name at the front of the candidate row and selects it, showing the cell boundaries over the source (grid view is turned on) — with the check on it runs only the grid stage, with it off it runs once with the values as set; the grid values it finds are loaded on the left but never written into a preset. Add to auto pixel size (px) and a manual grid's offset X/Y depend on the image, so Clean up uses them but presets and the settings remembered for next time don't store them (changing only these doesn't turn the save button red).

Cell color and palette

  • ⑥ Cell color: most frequent color after light snapping (default) · median · center pixel · mean · Center-weighted mean (the cell's center counts more) · Dominant-color weighted mean (groups similar colors and averages only inside the dominant group, so different fills such as skin and black clothing aren't mixed). Ignore cell border %, transparency threshold %. Color snap step is used only by most frequent color and dominant-color weighted mean.
  • ⑦ Palette: the methods are OKLCH grouping (default) · k-means (OKLab) · Median cut · Existing palette (palettes from the palette column and Lospec favorites) · Keep original colors · Distance grouping. OKLCH grouping merges colors whose lightness, chroma and hue differences are all within Group within L · C · H° (default 0.1 · 0.1 · 20) into one color — the color that groups the most pixels becomes a center first, a color within reach of several centers joins the nearest, and hue is ignored for near-gray colors. Distance grouping merges colors the same way when their difference measured with ⑧ Color distance is within Group radius (default 0.04, 0.005–0.3). Because OKLCH grouping ignores the hue of grays, a light gray can end up grouped with an apricot of the same lightness; distance grouping with CIEDE2000 as the color distance groups it with the white it looks like instead. With these two methods the limits decide the color count, so Colors and Auto are disabled. k-means and median cut use a color count of 2–64 or Auto (the elbow of the error curve, raised until small salient colors such as a red scarf are kept); the built-in preset Fewer colors (16) uses k-means with 16 colors. Don't optimize next to the method (only when the Palette step's Optimize is on; saved with the preset) keeps the palette method when optimizing and tries only that method's other values (color count, grouping range and so on). Palette colors (k-means, median cut and the two grouping methods): Original colors (default — after grouping similar colors, each group uses the cell color actually used most, so blurred edge colors can't pull a white robe toward grey) · Average colors (the group average, the old behavior). Edge cell weight 0–1 (0.25 by default, original colors only): when grouping colors and picking the auto color count, cells touching transparency and blurred cells between two neighbor colors (including between the outline and a fill) count only this much. One palette for all frames (default), dither None (default) · Bayer 2×2 · Bayer 4×4 (same as converting to palette colors) — Don't optimize next to the dither (on by default) keeps optimizing from changing the dither (a dither pattern's average color is close to the source, so it easily raises the score, yet zooming in shows a checkerboard or stray colored dots). Snap near-black colors to one outline color (the most-used palette color at or below the outline darkness — with original colors, an actual cell color). Dithering mixes two palette colors in light intensity (linear light) and compares the mix with the source in OKLab to set the ratio (e.g. a half black, half white pattern stands for sRGB 188 gray). The pattern is used only when the mix is still closer to the source than the nearest single color after adding how visible the pattern is (the lightness difference of the two colors counts fully, hue and chroma differences count half), and colors within a just-noticeable difference (OKLab 0.02) of a palette color are not dithered.
  • ⑧ Color distance (palette): the distance used when cells take a palette color (without dithering), for pinned-color matching, excluded-color replacement, the original-color pick and Distance grouping (the score uses the scoring color distance in 0. Optimize criteria). OKLCh hue-weighted (default — hue differences count more by the hue weight. The hue weight is 0–1000, default 2: 0 ignores hue differences, 1 equals OKLab distance, and very large values almost always pick a color of the same hue family first, before lightness and chroma) · CIEDE2000 · OKLab (the old straight distance). k-means and OKLCH grouping stay in OKLab, and dithering (Bayer) compares the light-blended mix in OKLab (see ⑦ Palette). Keep distinct hues (on by default): if a source color group with enough chroma (default 0.04) and area (default 4 cells) would turn into a palette color whose hue differs by 20° or more (e.g. small apricot ear shading → gold), that color is put in the palette — added with an automatic count, or swapped for the least important color with a fixed count (at most a quarter of the palette; pinned colors are never swapped). In-between colors blurred between two palette colors are not added. Optimizing the Palette step tries other values for both.
  • ⑨ Prefer shade family (on by default, under the color distance): if a palette color has a similar hue and chroma to the cell color (a lighter or darker shade of the same color), the cell takes the family member with the nearest lightness instead of a different-hue color of similar lightness. Dithering also never mixes in a chromatic color of a different hue — deep apricot hand shading no longer turns gold or gets gold dots. Optimizing the Palette step tries it on and off.

Cleanup and outlines

  • ⑩ Cleanup: remove orphan pixels (with a max contrast so pupils survive), fill 1-px holes, outline (as is · unify to the darkest color · ensure a closed 1-px outline), reduce L-corner doubles on outlines, ⑪ Fit outline to 1 px: By shrinking (default — the pixel size becomes the outer outline thickness, so the whole sprite scales down and the outline becomes 1 px; leftover double pixels get one light thinning pass; a manual grid size wins; the pixel size starts from the measured outline thickness so the outline band is exactly one cell, and may only move to a larger value that clearly fits the edges better, never to a smaller one such as half the thickness (a 2-cell outline); the thickness is measured at outline darkness 0.24 even if you lower it) · Thin outline only (keeps the grid's pixel size and peels up to 3 outline layers doubled inward, never breaking the line and leaving inner dark shapes such as eyes alone) · Redraw as vector (keeps the grid's pixel size like Thin outline only, traces the center line of the outline band touching transparency in the background-removed source, simplifies it and redraws it through the actual cell boundaries as a 1-px pixel-perfect line; old outline cells off the new line become transparent outside and the nearest inner color inside, so no double outline remains, and small dark shapes not touching the outline such as eyes stay; adjust with Vector simplify (px) and Keep small blobs (cells)) · Off.

Frame consistency

Per-step optimize and criteria

  • ⑯ 0. Optimize criteria (top of the settings column, saved with the preset) holds the budget and scoring rules for Clean up and Auto optimize. Trials and Seconds are the budget. Target colors lowers the score in proportion to the colors over the target (Auto, the default, ignores the color count; Strict next to it penalizes fewer colors than the target by the difference too). The Fidelity row sets how results are compared with the source: Cell by cell (default — each result pixel is compared only with its own source cell's color, so a stray colored dot inside an outline or a dither pattern costs points) · Blended with neighbors (blurred with neighboring cells before comparing — a dither pattern that blends from a distance counts as a match), and Center weighted (on by default — pixels near the cell center count more). Cell color is Dominant group (default — the largest group of similar colors in the cell, leaving out an outline or bleed crossing the cell edge) or Cell average, and Group range is how different colors may be within one group (OKLab, default 0.06). Scoring color distance (major shift, cell match) is OKLab, CIEDE2000 or OKLCh hue-weighted (with a weight for each of the lightness L, chroma C and hue H differences, default 1 · 1 · 2); it's separate from the palette's conversion distance and measures every candidate with the same ruler. Score weights (0 = ignore) sets how much each score item counts (0 = ignored).
  • ⑰ Optimize: only steps with this check on in their header (1. Background · 3. Pixel grid · 5. Cell color · 6. Palette · 7. Cleanup) are varied by Clean up and Auto optimize, starting from the values shown; steps with it off use their values as set (saved with the preset). A checked step tries everything it can change — Background: remove sticker border · Grid: pixel size, size jitter, pixel size source, local cell correction (with max shift and band in trials that use it) and a manual grid's offset X/Y · Cell color: cell color method, ignored cell border, transparency threshold, color snap step · Palette: palette method (all five, plus an existing palette when starting from one), color count, grouping range, group radius, palette colors, edge cell weight, color distance, keep distinct hues, prefer shade family, dither, snap outline color, outline darkness · Cleanup: cleanup on/off, outline fit mode, vector simplify, keep small blobs. Values tied to a method change only in trials using that method, and a palette method or dither with Don't optimize on is never changed. The pixel size is never shrunk without evidence: By shrinking searches only within ±15% of the source outline thickness; otherwise the search sweeps between the three estimates and their 2×, 3×, ½ and ⅓, going down only to 0.75× of the starting size and the auto estimate (smaller cells always improve fidelity, which would make results needlessly large). An exact multiple of a clean image keeps its pixel size. The pixel size is changed through Add to auto pixel size (px) for an auto grid, the pixel size for a manual grid and the factor for scale-factor output; a fixed output size skips it.

Search method and stopping conditions

  • It first tries each item on its own (7 spread-out values for numbers, every value for choices), then climbs from the best few points with small steps (shrinking the step when nothing improves). Identical settings are never run twice, and background removal and frame splitting are done once, so the trials run quickly on several threads.
  • When one search (a pass) ends with no further improvement, the same search runs again from the best result. A new pass also climbs from the top result not yet used as a start whose settings differ most from the best and from a small fixed nudge of the best, so it doesn't get stuck in one spot. A pass that raises the best score by less than 0.1 points doesn't stop the search right away: up to three more passes start from other top results and wider nudges before it stops, so optimizing an already optimized result doesn't give up after its first pass. Settings already tried are never run again. The same image and settings always give the same result when the run ends on the trial budget rather than the time limit.
  • Each preset stops at the Trials or Seconds of its 0. Optimize criteria, whichever comes first (one budget shared by all passes of that preset; 2000 trials and 120 seconds for a new preset). With Optimize grid fit first on and other steps optimized too, the grid stage uses up to half of it.

On the bundled sample (default settings, the earlier default items and budget — pixel size, color count, cell color method, cleanup and palette colors; 200 trials, 60 s) it took about 3 s and 162 trials to go from 70.3 to 80.8 (cells about 16.1 → 14.9 px, 26 colors, fill holes off, palette colors kept as original colors, 99% of outline pixels 1 px).

Local cell correction

  • ⑪ Local cell correction is enabled under Pixel grid on the left. Minimum cell size (px) is the average source-pixel size required to adjust boundaries; set it from 1 to 16 px (default 4 px). Lower values can correct small cells but may follow blurred-edge noise. Maximum shift is 5–99% of a cell and Band spans 1–32 cells; neighboring cell-width limits may constrain the actual shift. The grid stays straight when cells are below the selected threshold or no boundaries move. The selected result shows whether correction took effect. With Optimize on for 3. Pixel grid, Clean up and Auto optimize also try correction on and off along with the max shift and band.

Excluded and pinned colors

  • Color swatches and result pixels work the same way — Left-click: show where used · Right-click: exclude/restore. Right-click a swatch to exclude that color from the current result only, without rebuilding (only its pixels change, to the remaining color nearest their source cell's color, so N colors drops by exactly the number excluded; ⑫ the swatch stays at the end, dimmed, with a red border and a diagonal line), and right-click again to bring back the original result. Right-clicking a pixel in the large preview's result image or the enlarged view's result pane excludes the color currently shown there (if it's already a replacement for an excluded color, that replacement color). The last remaining color can't be excluded (the status line says so), and right-clicking a pinned color unpins it. Left-click briefly highlights that color's pixels in the result (other colors dimmed, each connected patch of that color outlined in yellow around its edge only) and the swatch itself — for an excluded swatch, where the color used to be. While colors are excluded, ⑬ "N colors excluded · Restore all" is shown; newly built candidates and auto-optimize results get the same exclusion, and it stays when applying (a color within OKLab 0.03 counts as the same color, so slightly different settings still match). Exclusions aren't saved in presets and are cleared when the source is replaced.
  • Pinned colors: the ⑭ + at the end of the swatches (Add color from source) starts an eyedropper (the + stays pressed). The source view on the left, the large preview's source image and the enlarged view's source pane show the eyedropper cursor and highlight the cell under it, and the border of every visible source image slowly brightens and dims in the accent color (about a 1.2 s cycle) to say "pick here" (it disappears as soon as the eyedropper ends); clicking a cell pins its representative color (using the selected candidate's cells and cell color mode). The eyedropper ends after one color (Shift+click keeps it on); Esc, right-click or pressing + again stops it. Like exclusions, a pinned color is added to the current result without rebuilding — the other colors, candidate order and scores stay; only pixels whose source cell color is closer to the pinned color than to their current color take it, so the color count grows by one, and unpinning puts those pixels back. A pinned color is never excluded. Pinned swatches get a blue border and a blue corner triangle (shown dimmed when unused); right-click one to unpin, and "N pinned colors · Clear all" is shown. Pinned colors carry over to candidates, auto-optimize results (never changed) and applying; they aren't saved in presets and are cleared when the source is replaced. Colors can't be excluded or pinned while you watch a running tile.

Background and color comparison

  • Background: ⑮ Remove sticker border (on by default) finds the white band around the outline and removes it (optimizing the Background step tries it on and off), and ⑯ Keep background (one color) keeps the detected background flattened to the background color. The one-pixel blended fringe between a solid background and the sprite is removed too. The score's Major color shift is how much a widely used color changed as a whole, and Fidelity is (opacity mismatches + structure loss inside cells + color difference) ÷ number of samples. Structure loss is how far the source pixels inside a cell scatter from the cell average; it is large for a cell that splits a sharp edge in half and doesn't depend on the result color. The color difference follows the Fidelity setting in 0. Optimize criteria: Cell by cell (default) compares each result pixel only with its own source cell's color using the scoring color distance, and Blended with neighbors converts the source cell averages and the result into lightness, red-green and blue-yellow channels in light intensity (linear light), blurs them with neighboring cells (lightness a little, hue more), then compares them in OKLab (the S-CIELAB approach — a 1 px alternating dither pattern that blends into the original color counts as a match).
  • ② The selected candidate is shown large, animated at the FPS, next to the matching source frame; the two images are labeled Result and Source.
  • Left-clicking a result pixel: press and release (without dragging) on a pixel in the enlarged view's result image to show where that color is used — its swatch is highlighted in both swatch rows with a thick accent border and a short grow-and-return pulse (scrolled into view if the row overflows), the clicked pixel is marked and the same-color regions are outlined (as with left-clicking a swatch) for 1.2 s, the status line shows the HEX value and output coordinates, and the color decision row for that pixel opens (Enlarged view). Right-click excludes or restores that color (see the swatches above).
  • Left-clicking a source cell: press and release (without dragging) on a cell in the enlarged view's source pane to outline that cell and its matching result pixel in blue; the result's swatch and same-color regions are highlighted, and the color decision row for that result pixel opens. The source image is not recolored. The status line shows "Source cell #representative → result #result" (the representative is the cell's color before the palette). Right-clicking a source cell does nothing. While the eyedropper is on, the click adds a pinned color instead.
  • A source cell whose representative color is black can still produce a yellow result: Fit outline to 1 px in Thin outline only or By shrinking mode replaces inner dark outline cells with nearby light colors to make the outline one pixel thick. Try switching outline fit Off to keep that dark cell. Local correction adjusts boundary positions instead of performing this recoloring.

Enlarged view

  • ㉑ The Color decision row: left-click a result pixel or a source cell in the enlarged view (when the eyedropper is off) and a Color decision (x, y) row appears above the swatches. It reruns that pixel with the same settings and shows the color at each step as a swatch and HEX value, in order: Cell color (cell color method) → Palette (Palette (prefer shade family) when the shade family rule picked something other than the nearest color, Palette (dithering) with dithering) → only the later steps that changed the color (snap outline color, redraw as vector, remove orphan pixels, fill 1-px holes, thin outline to 1 px, outline, reduce L-corner doubles, remove outer L corners, match neighbor frames, pinned color, excluded color). The last, bold color is the result. Hover a step name for its rule, or the cell color for its OKLCh lightness and chroma. Part (group) layers · skins

Draw parts of different sizes, like a character's head, body, arms and legs, for each frame, arrange them within a frame to use as an animation, and export them as per-part sprites too. You can also draw several sets (skins) of body types, outfits or gear with the same part setup and swap between them.

Groups and parts

  • ② Part layers go under a ① group layer.
  • Each part has ③ its own canvas size (e.g. Head 8×5) and ④ its own image in each frame.
  • ⑤ A part's position within the frame is shared by all frames.

Creating

  • In a new project (Ctrl+N), choose ① "Start with parts" and set ② the first part's name and size.
  • Frame·Layer > ③ New group (Ctrl+Shift+N)
  • Frame·Layer > ④ New part… (Shift+P) — adds to the current group, creating a group first if there isn't one. In the dialog, set ⑤ the name and ⑥ the size.
  • Right-click a layer name in the timeline → ⑦ "New group / New part…", or right-click a group → ⑧ "Add part…"

Viewing in the timeline

Group rows collapse and expand with ① a triangle, and ② their cells show the group's composite thumbnail. ③ Part rows are indented and show the name and size. ④ The skin chip after the name is the skin currently worn; click it to open the skin manager.

⑤ Hiding or locking a group also hides or locks its parts. Parts can be reordered only within their own group.

Arranging (group selected)

Selecting a group shows the full frame composite on the canvas.

  • ① Hover a part to see a dotted border and its name.
  • Drag to move it and set its position (applies to all frames; one undo step).
  • Click a part to ② select it, then use the arrow keys (Shift+arrow) to move it by 1/8px. Click an empty area or press Esc to deselect.

① Selecting a part layer shows ② only that part at its own size, with the rest dimmed around it. Coordinates are relative to the part.

  • Resize: Frame·Layer > ③ Part size… or right-click the part → ④ "Size…" (⑥ 9-direction anchor; drawn pixels stay in place).

Skins and slots

Each group has a list of named skins (at least one, "Default" at first), and ① only one of them is shown.

  • Skins in the same group replace each other (swap).
  • ② Different groups stack in layer order (overlay).

Example: a "base body" group at the bottom (skins: default, muscular, zombie), with "hair" and "armor" groups above it (the first skin, "none", is left empty and gear is drawn in the other skins).

The only thing that differs between skins is the image. The part list, sizes, positions, pivots and 9-slice are shared by all skins. Empty cells in skins other than the first inherit the first skin's image, so you only need to redraw the parts that change. ③ Inherited cells appear dimmed in the timeline, and once you start drawing on one it becomes that skin's own image.

Per-part choices and part-only skins

Within a group, a single part can wear a different skin (e.g. the body stays in ① the group skin "knight" and only the head wears ② "zombie"). The visible skin is decided in the order part override → ③ group's current skin → first skin.

You can also create a part-only skin that exists for just one part (e.g. a "hat" for Head). Create it with ④ This part's skins on the part row in the skin manager or from the part's right-click menu (⑥ → ⑦); it's marked "Individual" only in that part's list (⑤, ⑧).

Right-click a part-only skin card to ⑨ Promote to full skin, or right-click a full skin to ⑩ Demote to part-only.

Generate image → pixelate

Ask the Codex tab for something like "draw a knight with a sword", and instead of placing pixels one by one the AI calls the generate_pixel_art tool. Chickxel runs the Codex CLI on your computer (codex exec, Codex image generation) with your ChatGPT login (no API key) to generate a high-quality image, then turns it into pixel art the same way as Pixelate AI images (background removal, auto optimize, a shared palette and 1-px outlines) and inserts it. Each image takes about 30–90 seconds.

  • Drawing settings: the ① Drawing settings button (sliders icon) next to the question mark button at the top of the chat window opens a settings panel on the right, like the help panel. Only one of help and drawing settings is open at a time, and while it's open the button shows a red X. The panel also shows the ② Codex CLI status (logged in / not installed / not logged in).
  • Hover over an option or its ③ info icon for the longer explanation. Generate image shows only the generation options, Draw pixels directly shows only Use palette colors only, and Auto shows both.
  • Drawing mode: ④ Auto (default) in the Codex tab edits the current picture by placing pixels when the chat's Current file only is on, and otherwise tries Generate image → pixelate first. If it can't generate (no Codex CLI or a generation error), the same request is drawn with the pixel tools, followed by the same whole-picture review as Draw pixels directly. If you press Stop during generation, it doesn't fall back to drawing pixels. ⑤ Generate image → pixelate always generates and converts, and ⑥ Draw pixels directly has the AI place pixels one by one with the pixel tools. If you choose ⑤ or ⑥ yourself, that mode is kept. A Generate image setting saved by an older version switches to Auto once; a saved Draw pixels directly is kept.
    • ⑦ Use palette colors only (under Draw pixels directly — shown for Auto and Draw pixels directly, off by default, saved): when on, the colors the AI paints with the pixel tools (the draw_pixels legend, set_pixels, draw_shape, fill, replace_color's target color, the new_project background) are changed to the nearest color of the active palette (the same color distance as the Pixelate tool). Fully transparent (erasing) is still allowed; semi-transparent colors become the nearest opaque palette color. The tool result tells the AI what changed, e.g. "팔레트 색으로 맞춤: #E63228→#C81E1E", and each message also sends the palette colors (up to 64) so the AI draws with them from the start. It works in both the Claude and Codex tabs and doesn't affect generated images (the conversion's palette settings) or layer effects. When off, all colors and alpha are used as before.
  • Whole-picture review when drawing pixels: with Draw pixels directly (including Auto's fallback), the AI first reads your words and attached images together, lists the subject, size, proportions, pose, colors, style and anything to avoid, and plans the overall layout and where each part goes. Without an image, it works from the conditions you described. When a turn that changed pixels or parts ends, Chickxel automatically sends the AI the current canvas with all layers combined for a review. The AI scores the silhouette, limb placement and style out of 10 against your original request and images, fixes what's wrong, and looks at the whole picture again (up to three rounds of fixes; if it doesn't improve, it explains the remaining problems). The score is the AI's subjective judgment, not an exact similarity measurement. The review and fixes belong to the same undo step as the turn, and the extra AI turns take more time and usage. Generate image → pixelate doesn't use this review.
  • Inserting (⑫): as a New layer in the current document (one undo step together with the AI's turn) or as a New document. If the generated image is larger than the open canvas, you're asked first whether to expand the canvas or choose a crop position (see Answering the AI's questions).
  • Background: unless you mention a background, the image is generated on a plain transparent background with no scenery.

Limiting edits to the current file

Turn on ① Current file only next to Attach canvas below the input box before sending, and the AI edits only the file that's open when you send.

  • Inside that file it can draw, add layers, frames, groups, parts, skins, and layer effects, and tidy up layers.
  • Opening or creating other files, such as new projects or opening files, is refused (③ red line; saving still works).
  • The chat shows the scope (②), like Edit scope: current file "slime.chickxel" only. Turn it off to lift the limit from the next message.

Protecting locked layers

The AI never touches locked layers (or the parts of a locked group), whether or not Current file only is on.

  • Changing their pixels, name, visibility, opacity, part position or size, adding, changing, removing, or permanently applying their layer effects, or changing the group's skin or outfit is refused with a "locked" reason (①).
  • Deleting a frame where a locked layer has pixels, and resizing the canvas (including enlarging it to fit effects) while any layer is locked, are refused too. Reading still works.
  • Lock layers the AI must not change with the ② lock icon in the timeline.

Progress display

While a reply is coming in, the bottom line (①) shows what's happening (waiting for response, thinking, writing tool call, running in editor, writing reply) and the elapsed time.

Large jobs that draw many frames at once can take over a minute to prepare. If the received character count keeps growing, it's working.

Answering the AI's questions

When the AI needs a decision from you, a ① question card appears right above the chat input box. The AI doesn't pick an answer on its own and carry on. If you were on the other tab, the window switches to the tab that asked.

  • ② Click one of the options (2–5) to send that answer to the AI; the chosen answer is also added to the chat as a line.
  • ③ Other shows an Other answer box and a Submit answer button. Type your answer and press Enter or Submit answer.
  • ④ Cancel (or Esc in the answer box) closes the question; the AI won't guess an answer and carry on.

Generated image larger than the canvas: if an image made with image generation is larger than the open canvas, you're first asked to choose ② Expand canvas (keeps the existing art and enlarges the canvas) or Choose crop position. The canvas can't be expanded while a layer is locked. If the open document or the canvas size changes while the question is waiting, nothing is inserted.

  • ⑤ The Choose crop position window (opens when you choose the crop option): the area inside the highlighted outline on the source preview is what's kept. Drag the outline or click outside it to move it; arrow keys move it by 1 pixel and Shift+arrow keys by 10. Canvas space beyond the image stays transparent.
  • ⑥ Check the size and position to keep (in source pixels), then press ⑦ Keep this area to crop and insert that area. Cancel inserts nothing and leaves the existing art unchanged.

Chickxel also sends a Windows or macOS system notification when the AI asks a question, finishes, or hits an error (if the operating system allows notifications), so you know when to come back even while working in another window.

Edits the AI can make

The AI looks at the open image and edits it directly.

  • ① View the image, read pixels
  • ② Draw points, lines, rectangles and circles; fill, erase, replace colors
  • ③ Create and arrange frames, layers, tags, groups and parts
  • Add and switch skins, save and apply outfit presets
  • Add, change, and remove layer effects, apply them permanently, enlarge the canvas to fit them
  • Search and view references (search_references, get_reference), read style rules (get_style_rules), save the canvas as a reference and caption it (add_reference, set_reference_info) — see References: teach the AI your style
  • Canvas size, palette and colors, new project, open, save

The end of each ①② tool line shows in parentheses how long that tool took (e.g. get_image (22s), get_image (1m 20s)). For a failed tool it follows the error text, and it stays when you reopen the chat. A tool that is still running shows no time yet.

It saves only when asked. If a never-saved new project has changes, it asks whether to save before switching to another document.

Asking for layer effects

The AI can use the same layer effects as the Effects dialog. Effects don't change the drawing's pixels, so you can still change or remove them later in the Effects dialog or the ① timeline.

  • ② Ask things like "add a 1 px black outline to the character", "add a white hit flash on frames 3–4", "make it appear over the first 4 frames", or "put a shadow 2 px to the lower right".
  • Animated effects (hit flash, blink, shake, appear, and so on) play over the frame range you give. Without a range they cover the whole animation, as in the Effects dialog.
  • Your saved effect recipes and recipes from enabled packages can be added by name too.
  • It can also change the settings, frame range, on/off state, order, and clipping of existing effects.
  • Applying effects permanently (baking them into the pixels) and enlarging the canvas to fit effects that spill outside it happen only when you ask.

Effect changes (③) are part of the AI's reply, so one undo step (④) undoes them too. Effects on locked layers are never changed.

Undoing

Each AI reply is one undo step, so Ctrl+Z undoes it all at once. Each reply also comes with a ① result image and ② Undo this step / ③ Reapply buttons.

Editing or deleting the last message

Small ① pencil (edit) and ② trash (delete) icons sit under the last message you sent. They're disabled while a reply is coming in; a turn you stopped with Stop can be deleted.

  • Delete: removes that message and the reply, tool lines and result image after it. The previous message then gets the icons, so you can press again to step back one message at a time, all the way to the start.
  • Edit: removes it the same way, then puts its text and image chips (with the attached pictures, if they're still available) back in the message box so you can change it and send. Images of chats reopened from disk aren't resent.
  • If that reply changed the drawing and the step can still be undone, you're asked Also undo the drawing changes made in this exchange? — ③ Undo (same as Undo this step), ④ Keep drawing, or ⑤ Cancel (nothing is removed).
  • You can also delete or edit the last message of a reopened past chat (the drawing question isn't asked there).

The AI doesn't remember what you removed: after a delete or edit, the next message starts a new AI session and includes a recap of the remaining conversation.

Troubleshooting

  • If the AI can't connect to the editor, the chat shows a ① red line with the likely reason. Common causes are a proxy (HTTP_PROXY, HTTPS_PROXY), VPN or security software blocking connections to 127.0.0.1, or an outdated CLI.
  • Codex replies appear all at once after they're fully written, and show only the ② time, not the cost (Claude shows the cost too).
If you distribute an app with this feature to others, check Anthropic's and OpenAI's usage policies (restrictions on using subscription logins in third-party apps).

Language

Chickxel includes Korean and English. On first launch it picks the language that matches your computer, or starts in English if there's no match. You can add other languages yourself with a CSV file.

Changing the display language

  • Open ① Edit > Preferences… (Ctrl+,). ② Language is at the top.
  • Choose from the ③ Display language list and click ④ OK.
  • Click ⑤ Restart now to close the app and reopen it in the new language. If there are unsaved documents, you're asked first, just like when closing. Choose ⑥ Later to apply it the next time you launch.

Creating a new language

  1. Save a CSV file with ① Export translation CSV… in Preferences. You can open it in Excel, Google Sheets and so on.
  2. The first row is key,ko,en and the second row is #name,한국어,English. Add a new column at the far right with the language code in the first row (e.g. ja) and the language name in the second row (e.g. 日本語).
  3. Translate the text in that column. Braces such as {0} and {name} are placeholders for values, so keep them as they are (you may change their order).
  • Choose the file with ② Add language from CSV… and it appears in the ③ language list. Select it and restart to apply it.

Empty cells show the English text, so you can add your translation bit by bit. Adding the same language code again overwrites it.

Editing and removing built-in text

  • If you edit the ko or en column in an exported CSV and add it, only the edited cells override the built-in text.
  • ① Open language folder opens the folder containing the CSV files of added languages. Deleting a file removes that language from the list, or, for a file that edited a built-in language, restores the original text.
